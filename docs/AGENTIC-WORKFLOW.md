# Agentic Coding Workflow

> Status: living document, updated as each piece of agentic configuration is actually added and used — not written as a plan of what might be added.

This repository is built with Claude Code as a governed participant in the development process, not as an autocomplete tool. This document records what was configured, why, what it changed in practice, and where it failed.

## Where the agentic approach failed or needed correction

- **This project's own AI-usage log went stale for four phases.** `docs/AI-USAGE-LOG.md` has detailed per-phase entries for Phases 0-2 and then jumps straight to Phase 7 — Phases 3-6 (PRs #33-#66) landed with no matching log entry, despite `CLAUDE.md`'s explicit "docs updated in the same PR" convention. This was not caught until Phase 9's own docs-finalization pass. The honest fix was not to backfill a confident-sounding narrative for four phases from memory well after the fact (which the log's own "not reconstructed afterward" standard rules out) — it's disclosed as a real gap in `docs/AI-USAGE-LOG.md` itself, with real, verifiable evidence (PR numbers, other docs' own real entries from that window) offered as the closest honest substitute. This is the same class of failure the layer-dependency rule guards against in code — a stated convention that quietly stopped being followed — just in documentation instead of imports.
- **A lesson already read wasn't proactively applied one file over.** In Phase 7, a new integration test was written with no Ollama-reachability skip guard and failed CI outright — even though the file right next to it in the same directory carries an explicit comment stating that exactly this mistake had already caused a real CI failure in Phase 2. The comment had been read earlier in the same session. Fixed immediately once CI failed, but the miss itself — reading a warning and not generalizing it to a new file in the same session — was reported as feedback on the AI's own behavior, not just silently patched (`docs/AI-USAGE-LOG.md`'s Phase 7 entry).
- **A retrieval bug was hypothesized before it was verified, and the hypothesis was wrong.** In Phase 8, an unexpectedly-refused golden-set question's first explanation was "nondeterministic retrieval ranking" — a plausible-sounding guess that turned out to be entirely wrong once actually tested (four repeated fresh-process runs of the retrieval call alone were bit-for-bit identical). The real cause, a citation-marker omission on the LLM generation step, was one layer downstream of where the first hypothesis looked. The lesson generalized here: an AI's first causal story for an unexpected result is a hypothesis to test, not a conclusion to build the next 26 golden-set entries on — which is exactly why 3 sample cases were manually verified against the real running system before the full set was finalized, and why that verification step is what actually caught this.
- **A first-draft detection heuristic (regex `forbiddenPhrases` for injection resistance) missed the real failure it was built to catch**, because it was drafted against assumed wording rather than the model's actual output — also caught only by hand-verifying real cases before trusting the golden set, not by the regex logic being reviewed harder in isolation.
